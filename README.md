# Отток клиентов: сегментация и экономика удержания

Какие клиенты интернет-магазина товаров для животных перестают покупать и кому стоит предлагать скидку, чтобы она окупалась. Итог — план действий и схема эксперимента для проверки, а не accuracy модели.

- [memo](docs/memo.md) — выводы и план действий
- [questions.md](docs/questions.md) — ответы на частые вопросы
- [churn_definition.md](docs/churn_definition.md) — правила анализа, записанные до работы с данными; решения по ходу дописаны в конец

## Результаты

- Ушедший клиент — нет покупок 120 дней. Порог выбран по доле клиентов, которые возвращаются после паузы.
- Из активных клиентов за 120 дней уходят 35%: после одной покупки 68%, среди повторных покупателей 24%.
- Прошлая кампания удержания окупилась: +168 ₽ маржи на получателя. Окупаемость определяет сегмент (повторные покупатели собачьего корма +408 ₽), а не риск оттока.
- Модель ранжирует клиентов лучше правила (PR-AUC 0.808 против 0.758), но прибыли не добавляет, поэтому не внедряется.

## Как устроено

Данные синтетические. Генератор (`src/churn/generate.py`) закладывает известные ответы: цикл покупок по категориям, вероятность ухода и эффект прошлой кампании по сегментам (`src/churn/params.py`). Тесты проверяют, что анализ их восстанавливает.

Postgres (raw) → SQL-витрины (`sql/marts`) → признаки на дату прогноза (`features.py`) → правило и модели (`model.py`) → uplift и экономика (`uplift.py`).

Признаки считаются только по данным до даты прогноза. Тест сравнивает признаки, посчитанные по полной базе и по базе, обрезанной по этой дате.

Ноутбуки:
- `01_churn_definition` — порог оттока, когорты, портрет клиентов
- `02_rule_vs_model` — правило против модели
- `03_uplift_economics` — прибыль кампании, стратегии, размер эксперимента

## Запуск

Нужны Docker, make и [uv](https://docs.astral.sh/uv/).

```bash
uv venv --managed-python --python 3.12 .venv
uv pip install --python .venv/bin/python -r requirements.txt
uv pip install --python .venv/bin/python -e .
make test-all    # данные, Postgres на порту 5436, витрины, признаки, все тесты
make notebooks   # перевыполнить ноутбуки
```

`make reset-db` пересоздаёт базу с нуля.
